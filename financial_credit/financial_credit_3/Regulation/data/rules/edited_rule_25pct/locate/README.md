# Locate용 최소쌍 데이터셋 & Locate 방법 기록

- 데이터 생성기: `src/editing/generate_locate_pairs.py` (seed = 42 + rule번호, 재생성 시 동일 결과)
- Locate 코드: `src/editing/locate.py` / 실행: `shell/run_locate_all.sh`
- 결과 위치: `result/locate/rule{1..9}/n{1000..10000}/` (9 rule × 10 예산 = 90개)

---

## 1. 데이터셋: rule{1..9}.csv (rule당 10,000쌍)

### 1.1 쌍의 정의

한 쌍 = **완전히 동일한 문장 2개, 오직 해당 rule의 값만 현 threshold(θ) 경계 반대편**.

- base 문장: rule 값 = 통과측 → 라벨 1
- source 문장: rule 값 = 탈락측(`value_fail` 컬럼) → 라벨 0
- 나머지 12개 지표(컨텍스트): 쌍마다 새로 샘플링하되 두 문장이 공유

### 1.2 rule 값 샘플링 기준

학습 데이터 생성기(`generate_train_gaussian.py`)와 **동일한 분포 N(θ, σ)** 에서
양쪽 절단 샘플링 — 모델이 경계를 학습한 in-distribution 영역에서 locate하기 위함.
신뢰 마진 δ 이내(경계에 너무 가까운 값)는 제외해 모델 출력 불확실성으로 인한 노이즈 차단.

> 학습 방식과의 차이 (의도된 결정): ① 측면 절단은 쌍 정의(통과↔탈락)상 불가피.
> ② 마진 δ(≈0.27σ, 각 측 질량 ~20%)는 학습에 없던 사전 필터로 추가 —
> 경계 초근접 쌍은 locate의 유효쌍 필터(§2.3)로도 걸러지므로 δ는 보조 장치.
> ③ 파트너 지표가 rule 지표일 때 통과측 절단 (라벨 무결성 — §1.3 참고).

| rule | 지표 | θ | σ | 통과측 | δ | 표기 |
|---|---|---|---|---|---|---|
| 1 | 부채비율(%) | 200 | 15 | 아래(≤) | 4.0 | 소수 2자리 |
| 2 | 유동비율(%) | 100 | 7.5 | 위(≥) | 2.0 | 소수 2자리 |
| 3 | 자기자본비율(%) | 20 | 1.5 | 위(≥) | 0.4 | 소수 2자리 |
| 4 | 자본총계 | 0 | 500,000 | 위(>) | 10,000 | 정수 |
| 5 | 보통주자본비율(%) | 4.5 | 0.5 | 위(≥) | 0.09 | 소수 2자리 |
| 6 | 기본자본비율(%) | 6.0 | 0.5 | 위(≥) | 0.12 | 소수 2자리 |
| 7 | 총자본비율(%) | 8.0 | 0.6 | 위(≥) | 0.16 | 소수 2자리 |
| 8 | 단순기본자본비율(%) | 3.0 | 0.5 | 위(≥) | 0.06 | 소수 2자리 |
| 9 | 공제후자본양수 | 0 | 500,000 | 위(>) | 10,000 | 정수 |

- σ 산식(학습과 동일): 퍼센트 지표 = max(0.15·θ, 1)/2, 금액 지표 = 500,000 (절대값)
- 퍼센트 지표는 양수 제약. 금액 rule 4·9의 탈락측은 **음수** (θ=0 부호 경계)
- rule 4·9 값이 ±150만 이내인 이유: 모델이 부호 경계를 학습한 gaussian 데이터가
  N(0, 50만)이었기 때문 (실데이터 스케일 100억~400조와 다름에 유의)

### 1.3 컨텍스트(나머지 12개 지표) 샘플링 — θ-고정 + 파트너 1개 (학습 재현)

> **이력**: 초기 버전(`locate_random_context/`)은 컨텍스트를 각자의 통과 구간에서
> 독립 uniform으로 뽑았는데, 상관 지표끼리 모순 조합이 생겨(예: 자기자본비율 20 +
> 부채비율 50은 회계 항등식상 불가능, 자본비율 서열 보통주≤기본≤총자본 역전)
> rule 3·6·7의 유효쌍이 29/2,071/1,579까지 붕괴했다. 학습 gaussian 방식을 재현한
> 현 버전으로 셋 모두 100% 회복 (256쌍 스모크 검증).

학습 gaussian 생성기의 컨텍스트 구성을 그대로 재현한다:

1. **고정값**: 타겟 rule 제외 12개 지표를 학습 때의 고정값으로 — 퍼센트 지표는
   각자의 threshold(부채비율 200.0, 유동비율 100.0, 자기자본비율 20.0, 보통주 4.5,
   기본 6.0, 총자본 8.0, 단순 3.0, ROA 0.3, 예대율 100.0), 금액 지표는 1
   (자본총계, 공제후자본양수, 영업흑자, 이익잉여금양수). 고정값은 전부 통과.
2. **파트너 1개 흔들기**: 행마다 나머지 12개 중 1개를 랜덤 선택해 학습과 동일한
   N(θ_p, σ_p)로 샘플링 (학습의 지표쌍 순환 재현, 문맥 다양성 확보).
   - 파트너가 rule 지표면 **통과측으로 절단** (라벨 오염 방지 — 학습과의 유일한 차이)
   - 파트너가 distractor(ROA·영업흑자·이익잉여금·예대율)면 양측 자유 (학습 그대로)
   - 선택된 파트너는 CSV의 `partner` 컬럼에 기록

### 1.4 문장 렌더링과 토큰 정렬

- 문장은 **`format_prompt`(src/models/test.py) 단일 소스**로 렌더 — 학습·평가와 템플릿 완전 동일.
  CSV에는 문장을 저장하지 않고 지표값만 저장 (locate 시점에 렌더).
- **토큰 정렬**: base/source 문장을 실제 토크나이저(XLM-R sentencepiece)로 인코딩해
  토큰 수가 다르면 rule 값만 재샘플링 (최대 3회). 그래도 불일치하면 `token_aligned=False`로
  유지 (locate가 span 정렬로 처리). 실측 정렬률:

| rule | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 정렬률 | 100% | 100% | 99.4% | **64.5%** | 97.5% | 95.6% | 94.3% | 99.4% | **80.3%** |

(rule 4·9는 음수 "−" 토큰 때문에 구조적 불일치 — 정상)

### 1.5 라벨 무결성

전 쌍에 대해 `check_rule_labels.compute_rule_labels`로 **base=1, source=0** 기계 검증.
하나라도 어긋나면 생성 중단(assert).

### 1.6 CSV 스키마

```
pair_id, <13개 지표 컬럼 (base 기준)>, value_fail, base_label, source_label, token_aligned, partner
```

## 2. Locate 방법: 어떤 기준으로 위치를 찾는가

### 2.1 개입 방식 — interchange intervention (residual stream)

base 문장을 forward하다가 **특정 (층, 위치)의 hidden state 하나만 source 문장 것으로
교체**하고, 최종 분류 확률이 얼마나 뒤집히는지(indirect effect, IE)를 측정한다.

```
IE_p2f(layer, group) = P_patched(라벨0) − P_base(라벨0)     # 통과→탈락 방향
IE_f2p(layer, group) = P_patched(라벨1) − P_source(라벨1)   # 탈락→통과 방향 (역방향)
```

- 교체 지점: 각 encoder layer(0~23)의 **출력**(residual stream). MLP/attention 분해는
  피크 층 확정 후 2차 분석.
- IE ≈ 1 → 그 (층, 위치)가 rule 판정 정보를 전부 운반 / IE ≈ 0 → 무관.

### 2.2 위치 그룹 (6개)

값 span의 문자 위치는 `format_prompt`와 동일한 세그먼트 조립으로 정확히 추적하고,
tokenizer offset mapping으로 토큰 위치로 변환한다.

| 그룹 | 정의 | 보는 것 |
|---|---|---|
| value_last | rule 값의 마지막 토큰 | 숫자 정보의 집계 지점 (편집 key 후보 1순위) |
| value_all | rule 값 토큰 전체 | 값 정보 전체 |
| name | 지표명 토큰 (예: "부채비율") | 판정 결과가 지표명으로 이동하는지 |
| cls | `<s>` (위치 0) | 분류 헤드가 읽는 최종 집계 |
| q_last | 문장 끝 질문의 마지막 내용 토큰 | 후반 브로드캐스트 |
| ctrl_roa | ROA(distractor) 값 토큰 | 대조군 — 여기서 IE가 뜨면 전역 확산 신호 |

**span 정렬**: base/source의 값 텍스트가 달라 토큰 수가 다를 수 있음 →
값 span은 **마지막 토큰 기준 끝에서부터** 짝지음(숫자 집계는 마지막 토큰에 수렴),
그 외 그룹은 내용이 같으므로 각자 문장에서 계산된 위치끼리 순서대로 짝지음.
(그룹 → 토큰 인덱스 매핑 실례는 `result/locate/README.md` 참고)

### 2.3 유효쌍 필터

pre-edit 모델이 **base→1, source→0을 모두 정답 예측(argmax)** 한 쌍만 집계에 포함.
모델이 헷갈리는 경계 샘플의 노이즈를 제거 (`pair_ie.npz`의 `valid` 마스크).

### 2.4 예산별 집계와 피크 선정

- 쌍별 IE를 전부 저장(`pair_ie.npz`: [10,000쌍 × 24층 × 6그룹 × 2방향], float16)
- 예산 n ∈ {1k, ..., 10k}: **앞에서부터 n쌍 중 유효쌍**의 IE 평균 → 히트맵
  (`n{n}/heatmap_{p2f,f2p}.csv`)
- **피크 층 = value_last 그룹의 |IE| 최대 층** (`meta.json`의 `peak_layer_*`)
- MEMIT용 층 구간 = [피크−2, 피크+2] (`memit_window_*`)
- 예산 증가에 따른 피크 층 안정성 = locate 데이터 효율성 분석 자료

### 2.5 실행 조건

모델 `yongukpark/xlm-roberta-large-rule`, bf16, batch 32, max_length 256.
GPU 0/1/2에 rule 3개씩 분산 (`shell/run_locate_all.sh`), rule당 약 40분.

### 2.6 해석 참고 (rule 1 스모크 관찰)

0~15층: value_all이 정보 보유 → 15~19층: **지표명(name) 토큰으로 판정 이동**(비교 연산 구간 추정)
→ 20~22층: 문장 전체 브로드캐스트 → 23층: `<s>` 집계. 편집 후보는 값→지표명 전이 구간.
